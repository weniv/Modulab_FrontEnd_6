* http: 통신 규약(protocol) - 우리 통신할 때 이렇게 저렇게 하자!
* http를 왜 front-end 개발자가 배워야 할까요?
    * fetch, axios 등으로 API를 호출할 때 그 형식에 나오는 PUT, DELETE, POST, GET 등의 의미가 다 여기서 나온 개념입니다.
    * 403, 404, 500 등의 상태 코드(status code)도 여기서 나오는 개념입니다.

* www.google.com: URL, 도메인 (이름)
* 172.217.209.147: IP(주소)
* 80, 443, 8080: PORT(문)
    * 172.217.209.147:443: IP + 포트번호
    * www.google.com:443: 도메인 + 포트번호
    * 보통은 443(https), 80(http) 포트를 생략함
    * 실제 운영 페이지
        * 서버는 제 책상 오른쪽 아래에 있었고(옜날에....)
        * www.paullab.co.kr:443: 메인 페이지
        * www.paullab.co.kr:8080: 제주코딩베이스캠프 페이지
        * www.paullab.co.kr:10000 ~ 20000: 학생용 포트폴리오 페이지
        * www.paullab.co.kr:5000: 로그인 페이지

* 참고
    * 포트는 0번부터 1023번까지는 건드리지 않습니다. 보통 5000번대 이상을 사용하는 것이 관례입니다.

| 포트 범위          | 이름                 | 설명                     |
|------------------|--------------------|------------------------|
| 0번 ~ 1023번      | 잘 알려진 포트(well-known port) | HTTP(80), HTTPS(443) 등    |
| 1024번 ~ 49151번   | 등록된 포트(registered port)    | 특정 애플리케이션용          |
| 49152번 ~ 65535번  | 동적 포트(dynamic port)        | 임시 연결용                 |

* http 요청 메서드
    * GET - 주로 리소스 취득 (URL 뒤에 이어붙이는 방식 - 작은 값들)
        * GET 예제: https://www.example.com/
        * GET 예제: https://www.example.com/api/products/12345
        * GET 예제: https://www.example.com/api/products?category=books&sort=price_asc
    * POST - 주로 리소스 생성 (Body에 붙이는 방식 - 상대적으로 큰 용량)
    * PUT - 리소스의 모든 것을 업데이트
    * DELETE - 리소스 삭제
    * PATCH - 리소스의 일부를 업데이트
    * HEAD - HTTP 헤더 정보만 요청, 해당 자원의 존재 여부 확인 목적.
    * OPTIONS - 웹서버가 지원하는 메소드 종류 반환 요청
    * TRACE - 요청 리소스가 수신되는 경로 확인
    * CONNECT - 프록시 서버로의 터널링을 통해 양방향 통신을 시작

* 과제: 아래 코드를 사용해서 GET, POST, PUT, DELETE 요청을 보내보세요. 내용은 https://api-guide.weniv.co.kr/eduAPI/specification/product 를 참고해주세요. GET 요청은 생략이 가능합니다. 아래 있는 번호는 753입니다. 이 번호는 1번 ~ 1000번 사이에 있는 아무 숫자나 사용하시면 됩니다. 실습하실 때에는 디스코드에 번호를 남겨주세요. 다른 사람이 내 게시물 수정 및 삭제하는 것을 방지하기 위해서입니다.
```
fetch('https://dev.wenivops.co.kr/services/fastapi-crud/753/product', {
  method: 'GET',
})
  .then((response) => response.json())
```

* 동작 방식 정리
    1. fetch로 url과 method를 지정해서 요청을 보냄
    2. 브라우저가 아래와 같은 텍스트로 된 http 요청(request)을 서버로 보냄
        ```
        GET /services/fastapi-crud/753/product HTTP/1.1
        Host: dev.wenivops.co.kr
        Connection: keep-alive
        ...
        ```
    3. 서버가 요청을 처리하고 아래와 같은 텍스트로 된 http 응답(response)을 브라우저로 보냄
        ```
        HTTP/1.1 200 OK
        Content-Type: application/json
        Content-Length: 1234
        ... 
         
        { "id": 1, "name": "Product A", "price": 100 }
        ```

* 프론트엔드 개발자가 알아야할 응답코드
```
// 상태코드 보기
fetch('https://dev.wenivops.co.kr/services/fastapi-crud/352/product', {
    method: 'GET',
    })
    .then((response) => {
        console.log('응답 상태 코드:', response.status);
    })
```

위와 같이 응답코드를 확인할 수 있다면 if 등으로 분기할 수 있을 것입니다.

* 200번대 - 성공
    * 200 OK: 요청이 성공적으로 처리되었습니다.
    * 201 Created: 요청이 성공적으로 처리되었으며, 새로운 리소스가 생성되었습니다.

* 400번대 - 클라이언트 오류
    * 400 Bad Request: 잘못된 요청입니다. 서버가 요청을 이해할 수 없습니다.
    * 401 Unauthorized: 인증이 필요합니다. 유효한 자격 증명이 제공되지 않았습니다. => 프론트엔드 개발자는 로그인 페이지로 이동시키는 등의 처리를 해야 합니다.
    * 403 Forbidden: 서버가 요청을 이해했지만, 권한이 없어 접근이 거부되었습니다. => 프론트엔드 개발자는 접근 불가 안내 페이지나 메인 페이지 등으로 이동시키는 등의 처리를 해야 합니다.
    * 404 Not Found: 요청한 리소스를 찾을 수 없습니다. => 프론트엔드 개발자는 404 페이지로 이동시키는 등의 처리를 해야 합니다.

* 500번대 - 서버 오류
    * 500 Internal Server Error: 서버 내부 오류입니다. 서버에서 요청을 처리하는 중에 문제가 발생했습니다.
